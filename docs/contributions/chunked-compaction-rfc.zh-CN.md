# RFC草稿：显式、有界的长文档分片处理

状态：本地提案，未实现、未发布。与超窗错误兼容PR分开。

## 目标与非目标

目标：让超过模型单次窗口的文档可以分块摘要或检索，保留出处和可追溯性。

非目标：无限上下文、无损压缩、自动扩大KV、默认改写`/v1/messages`、代替客户端会话状态管理。

## 推荐第一阶段：独立文档工具

输入：本地文档/文本、任务类型（全文摘要或定点问答）、最大块预算、最大输出、取消信号。

处理：

1. 文档按章节/段落/代码符号切分；极长单段再按token切，保持明确源偏移。
2. 用Strata同一tokenizer/template计数，指令+文档块+输出+安全余量必须放得下。
3. 摘要任务走map/reduce；问答任务优先检索相关块。
4. 每次map输出结构化摘要、来源、未确认事实，不执行工具、不把原文当系统指令。
5. reduce后重新计数；最多3层，摘要未缩小就终止并反馈，不能无限重试。
6. 原文不覆盖；缓存摘要及内容哈希，文件变化后失效。
7. 单GPU并发1，可取消，报告块序号、数量、耗时和预计剩余步骤。

实验起点：正文16K–24K/块、摘要1K–2K/块、最终4K–8K；不是未经测量的生产默认。

## 第二阶段：会话压缩是否需要服务端兜底

先验证Claude/Pi/OpenCode客户端原生压缩。若仍需兜底，应单独API或显式opt-in，返回客户端可保留的压缩结果，而不是隐式替换会话。

必须保护：系统指令、当前用户目标、未完成工具调用、调用/结果配对、权限约束、文件路径及关键代码。只能压缩完成的历史组。

## 安全与资源边界

- 接收字节数、文件类型、块数、归并层数、超时和缓存容量均有限。
- 来源文本是不可信数据，摘要流程不得调用业务工具。
- 会话/用户隔离缓存；不要仅以部分正文哈希跨用户共享敏感摘要。
- 不持有生成互斥锁再递归HTTP请求同一服务，避免单引擎死锁。
- 禁止自动重复已产生副作用的工具操作。
- 明确显示有损压缩，允许回查原文和出处。

## 验收测试

- 单块刚好合规、超1token、超长单段、空文件、非UTF8、大代码块。
- 摘要输出过长、没有变短、超时、取消、引擎繁忙、进程重启。
- tool_call/tool_result配对与未完成调用不被切断。
- 注入性原文不能改变摘要规则或触发工具。
- 缓存命中/失效/隔离；后续轮次不重复摘要同一前缀。
- 定点检索准确率、跨块事实、引用来源正确率和重要细节丢失率。
- 本机记录冷/热耗时、prefill/decode、峰值RAM/VRAM及与直接检索的对照。
